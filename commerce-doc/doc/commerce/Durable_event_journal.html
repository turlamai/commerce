5 Durable event journal🔗ℹ

Server processes explicitly require "commerce/journal.rkt", "commerce/storage.rkt", and "commerce/storage/sqlite.rkt". None is re-exported from the default product-safe facade.

(open-sqlite-commerce-storage database-path) -> commerce-storage?

  database-path : path-string?

Opens or creates a Commerce-owned SQLite database. Schema v3 uses WAL mode, full commit synchronization, foreign keys, and database triggers that reject updates or deletes of accepted event and entitlement-lineage evidence. Schema v1 and v2 databases migrate in place without rewriting existing rows. The v3 lineage tables retain stable entitlement roots and contiguous revisions with exact unsigned Permit payload bytes; no signer or signed-credential storage is exposed.

(journal-accept! storage raw-payload event #:received-at received-at)

  -> journal-acceptance?

  storage     : commerce-storage?

  raw-payload : bytes?

  event       : payment-event?

  received-at : exact-nonnegative-integer?

Copies and hashes the exact authenticated bytes, then durably stores them with the canonical payment-event snapshot. The acceptance disposition is ’accepted for a newly committed row or ’replayed for an exact retry. The same provider event id with changed raw or canonical content raises an exn:fail:commerce whose code is ’event-conflict. Digest mismatch is rejected before persistence.

(journal-ref storage provider event-id)

  -> (or/c journal-record? #f)

journal-ref returns the original sequence, canonical event, immutable raw payload, and receive time.
