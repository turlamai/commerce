4 Pancake webhook authentication🔗ℹ

Server processes explicitly require "commerce/pancake.rkt". This module authenticates provider-native evidence and is not re-exported by the default facade.

(verify-pancake-webhook

 raw-body signature-header

 #:environment environment

 [#:keyring keyring]

 [#:now-ms now-ms]

 [#:past-tolerance-ms past-tolerance-ms]

 [#:future-tolerance-ms future-tolerance-ms])

 -> pancake-webhook?

  raw-body        : bytes?

  signature-header : string?

  environment     : (or/c 'test 'production)

Verifies the X-Waffo-Signature RSA-SHA256 signature over the decimal millisecond timestamp, one period byte, and the exact copied request bytes. The default window accepts up to 45 minutes of retry age and one minute of future clock skew. JSON parsing happens only after verification. The signed payload’s mode must match the explicitly selected environment, and duplicate top-level fields are rejected.

The returned value exposes environment, envelope identifiers, event and store metadata, data, immutable raw bytes, their SHA-256 digest, and the signature timestamp through the pancake-webhook-* accessors. It is provider-native evidence and is not yet a canonical payment-event.

(pancake-webhook-keyring test-public-key production-public-key)

 -> pancake-webhook-keyring?

An explicit keyring supports controlled provider key rotation. Test and production keys must be non-empty and distinct. Authentication and payload failures raise redacted exn:fail:commerce values; raw bodies, signatures, and key contents are never included. Codes distinguish missing or malformed signature headers, invalid or out-of-window timestamps, invalid signatures, invalid configured public keys, invalid payloads, and environment mismatch.

4.1 Pancake active one-time order verification🔗ℹ

(pancake-order-binding

 merchant-external-id product-id offer-id subject-id amount currency-exponent)

 -> pancake-order-binding?

Records the server-side expectation created with checkout. The merchant external id is a random correlation reference of at most 128 characters. It maps locally to one provider product, stable Offer, opaque stable subject, expected money value, and explicit ISO 4217 exponent from zero through four. It must not contain or substitute for the subject identity.

(make-pancake-merchant-client

 merchant-id private-key-pem

 #:environment environment

 [#:connect-timeout-seconds connect-timeout]

 [#:request-timeout-seconds request-timeout]

 [#:transport transport]

 [#:clock clock])

 -> pancake-merchant-client?

Creates an opaque server-side client. The RSA private key is parsed once and is not exposed by accessors. The client signs one POST /v1/graphql merchant read with RSA-SHA256/PKCS#1 v1.5. Both environments use https://api.waffo.ai/v1/graphql; the explicit environment is verified against the returned order’s testMode. Defaults are five seconds to connect and ten seconds for response headers and body. Reads follow no redirects, carry no idempotency key, and make no implicit retry.

(verify-pancake-onetime-order client webhook binding) -> payment-event?

Requires an authenticated order.completed webhook, actively reads its one-time order, and checks order id, completed status, environment, store, merchant external id, product, the webhook payment id and succeeded status, currency, and exact payment total. Decimal display money is converted directly to configured minor units without floating point. Only a complete match constructs the canonical event.

Transport failure and HTTP 408/429/5xx raise retryable pancake-order-unavailable. Merchant authentication, GraphQL rejection, missing or malformed orders, and each semantic mismatch have separate typed, redacted codes. The optional transport and clock arguments on make-pancake-merchant-client exist for deterministic integration testing; production callers normally leave them at their secure defaults.
