# 即刻收直连时长包适配器

[English](nowpay-direct.md) · [权威来源和签发边界](decisions/0027-nowpay-direct-duration.md)

`commerce/nowpay-direct` 是显式服务端模块，调用正式网关的 `charge.query` 和 `purchase.consult`。先验证响应原始字节的 RSA2 签名，再用 Permit 的严格 JSON 读取器拒绝重复字段，核对唯一 MONTH 档位、整数分价格及上海时区有效区间。返回值保留本次实际请求的应用用户和商品绑定；不能从外部 JSON 构造已验证决策。

访问决策不是支付收据。响应没有回显全部请求绑定，因此单独保存的签名响应不能证明受益人。独立签发进程必须自行发起受限的实时 HTTPS 查询，不能接收网页返回、前端付费标记或其他进程传入的 ALLOW 来开通。不伪造付款流水，也不提供退款写操作。

标准安装后，使用 `raco commerce nowpay /etc/commerce/nowpay-direct.json charge` 只读查询商品，输出收费状态、核对过的档位、整数分价格和周期；不读取 Permit 私钥，也不下单。新增购买同时要求 ENABLED、唯一匹配的月档位和配置价格。停止新增收款不直接撤销已有有效权益。

`serve` 从标准输入读取一条有大小限制的严格 JSON 请求，再输出一条 JSON。使用包内 systemd socket 和每连接服务单元，独立 `commerce-issuer` 账户及仅其可写的 0700 状态目录。商户和 Permit 私钥分别保存为 0600 文件，公开 Publy 进程不能读取。socket 只允许签发账户和产品组连接；其他产品必须使用独立配置、socket、账户和状态，不共享 root 或开发包作用域。

按包内配置模板填写真实资料，商户/商品审核、商品查询、额度和应用验收完成前保持 `purchasing_enabled=false`。本接口不创建商品；商品资料在官方小程序配置。SDK 的 `outProductId` 对应协议字段 `biz_content.out_product_id`，`external_buyer_id` 使用应用内部稳定用户 ID。

每次请求包含协议版本、固定服务 ID、应用用户 ID 和随机 64 位小写十六进制 nonce。独立进程实时查到 ALLOW 后，签发普通 Permit 权益；`jrtx.site/commerce/nowpay-direct` 扩展绑定本次 nonce、服务、商品、平台有效期和 30 秒新鲜度。产品必须独立验签并核对这些绑定，每次接纳和队列执行前都重新检查，不能拿旧响应给新任务放行。有效期按平台返回的上海时间转换 UTC，不能自行换算成 30 天。

私有 SQLite 状态串行处理观察结果，递增账户权益修订，并在返回前原子保存原始签名响应和最终凭据。同一 nonce 的相同请求可在短时限内恢复同一结果，换账户或过期重放会拒绝。该库不属于付款流水，公开边缘进程不能写入。备份和原始响应受限保存，归档时遵守运营者披露的保留规则，不抹掉当前谱系及重放保护。

测试用构造器允许注入传输和时钟；生产 CLI 配置不允许注入这两者或提供伪造响应。普通错误只含类型码，不输出密钥、购买链接令牌、原始支付数据或解析异常。模拟测试通过不代表真实购买、退款撤权、到期恢复和商户额度已经验收。

正式签发强制使用原生 Ed25519，缺少原生提供者时拒绝签发。可用 `purchase_buyer_allowlist` 限定获得购买入口的应用用户；空数组不允许任何用户，省略该项时仍须开启 `purchasing_enabled` 才能面向全部用户提供入口。此发布控制不影响已有 ALLOW 权益。
